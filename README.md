# Claude Workspace

> 面向 Windows 的本地私人助理与多工程 Claude Code 桌面工作台

[快速开始](#快速开始) · [私人助理 Agent](#私人助理-agent) · [定时任务](#在聊天中创建定时任务) · [企业微信](#企业微信机器人) · [数据与安全](#数据与安全) · [常见问题](#常见问题)

Claude Workspace 在一个桌面窗口中组织本机 Claude Code 工程会话，并对外提供多个独立的私人助理 Agent。助理可以在客户端内直接聊天，也可以从主人的企业微信单聊继续同一段上下文；网页读取、邮件处理、信息推送、定时执行以及其他 Claude Code 能力都属于助理能力。Claude Code 只是助理的本地执行引擎，不是私人助理的对外入口；因此不再有独立的“网页信息推送自动化”产品。

客户端侧栏提供“私人助理”和“开发工作台”两个可切换的一级 Tab；共享的 Claude 运行环境置于 Tab 之上，私人助理 Tab 下直接列出助理，列表底部提供配置当前助理和新建助理，右侧主工作区显示当前主人会话，工程与会话、Claude Code 终端控制机器人统一归入后者。

私人助理主工作区沿用开发工作台的紧凑工具栏布局：顶部显示“私人助理 / 助理名”和单行状态摘要，聊天与定时任务内容从下方开始。

“开发工作台”用于本机工程、Claude Code 交互式会话和终端远程控制，不是 Claude Code 账号、模型或权限配置页。

> [!IMPORTANT]
> Claude Workspace 不包含、代理或重新实现 Claude Code。它使用电脑上已经安装并登录的 Claude Code CLI。文件、命令和工具在本机执行，模型请求仍由 Claude Code 发往你配置的 Anthropic、Amazon Bedrock、Google Vertex AI、Microsoft Foundry 或企业网关；这不是离线模型客户端。

## 功能亮点

| 能力 | 说明 |
| --- | --- |
| 私人助理 Agent | 创建多个独立助理，在客户端聊天；主人企业微信单聊与本地共享同一段连续上下文 |
| 完整主人能力 | 助理加载主人本机的 Claude Code 用户、工程和本地设置，可使用默认工具、Skills、Chrome 和已配置 MCP |
| 会话内定时任务 | 直接在聊天中让助理创建、修改、暂停、运行或删除任务，无需复杂配置页 |
| 独立任务执行 | 每次任务运行使用全新的一次性 Claude 会话，不读取或污染主人聊天历史 |
| 异常可见 | 执行失败、超时、中断、重叠跳过、启动恢复和企业微信投递失败都有持久记录 |
| 多个企业微信智能机器人 | 多个助理可各自绑定并同时在线；与 Claude Code 终端控制机器人明确分开 |
| 多工程工作区 | 添加多个本地项目，以真实工程目录作为 Claude Code 的 `cwd` |
| 原生终端体验 | 保留 Claude Code TUI、权限确认、斜杠命令、ANSI 输出和键盘交互 |
| 明暗主题 | 在共享运行环境卡片下切换暗色或白色背景，选择会保存到本地工作区 |
| 文件变更查看 | 查看 Git 变更、相对 `HEAD` 的对比和磁盘最新内容，支持 Markdown、GFM 与 Mermaid |
| 企业微信远程回复 | Claude Code 终端等待权限、问题、计划确认或完成/失败时，可通知主人并接收远程输入 |

## 快速开始

### 运行要求

- Windows 10 或 Windows 11，x64 架构。
- 已按照 [Claude Code 官方文档](https://code.claude.com/docs/en/setup) 安装并登录 Claude Code。
- 能够访问 Claude Code 所使用的模型服务或企业网关。
- Git（仅“文件变更”侧栏需要）。
- Node.js 只在从源码开发或构建时需要。

先在普通 PowerShell 中确认 Claude Code 可以独立运行：

```powershell
where.exe claude
claude --version
claude
```

### 安装和首次使用

1. 使用 Windows 版 7-Zip 或其他兼容工具解压 `Claude Workspace-<版本号>-x64.7z`，不要直接在压缩包内运行。
2. 双击 `Claude Workspace.exe`。
3. 点击“选择工程文件夹”，添加实际项目根目录。
4. 在工程下新建 Claude Code 会话，或创建相互隔离的临时会话。
5. 在“开发工作台”Tab 使用左侧列表或 `Ctrl+K` 切换工程与会话。
6. 需要私人助理时，点击“私人助理”Tab，在左侧选择助理；列表底部可配置当前助理或新建助理，右侧会直接打开主人会话；创建或配置助理时可在同一张表单直接填写并绑定企业微信智能机器人。运行目录独立选择，不需要先加入开发工作台。

程序会自动查找原生安装的 `claude.exe` 和 npm 安装产生的 `claude.cmd`。自动检测失败时，可以手动选择 `.exe`、`.cmd`、`.bat` 或 `.ps1` 启动文件。

“开发工作台”左侧的“新会话启动命令”默认首选 `claude`，也可以选择 `claude --dangerously-skip-permissions` 跳过权限确认。该选择适用于下一次新建的工程会话或临时会话，成功创建后会恢复为普通 `claude`。每个会话会保存自己的启动模式，重启会话或重新打开客户端后仍保留；跳过权限确认的会话会在顶部显示对应标记。

侧栏顶部的“背景”可以在“暗色”和“白色”之间切换。主题选择会写入 `workspace.json`，下次启动继续使用；终端 ANSI 调色板、侧栏、弹窗和私人助理页面会同步切换。白色背景下终端会自动提高低对比度 ANSI 文本的明度差，避免高亮白字与背景融为一体。

## 私人助理 Agent

私人助理独立于接入渠道，不是企业微信机器人的别名，也不是 Claude Code 的远程入口。每个助理保存自己的名称、指令、独立运行目录、主人身份、连续 Claude 会话和定时任务；没有企业微信也可在桌面完整使用。运行目录可以与开发工作台工程完全不同，选择时不会自动新增工作台工程。

### 创建并聊天

1. 在左侧打开“私人助理” Tab，点击“新建助理”。
2. 填写名称并选择运行目录；助理指令可选。
3. 保存后直接发送消息。输入框右下角可以上下拖动调整高度，最多占窗口约 40% 的高度；`Enter` 发送，`Shift+Enter` 换行；在主人聊天输入框中使用 `Ctrl+X`（macOS 为 `Command+X`）剪切选中文本；同一助理按顺序处理消息，不同助理可并行。尚未开始处理的消息会列在输入框上方的“排队中的消息”区域，可逐条点击“撤销”；消息开始处理后才会进入聊天记录，撤销的排队消息不会进入聊天记录。
4. “关闭会话”只结束当前常驻 Claude 进程并保留上下文；下一条消息会恢复已保存的 session。操作完成后输入框会自动获得焦点，仍可立即输入下一条消息。
5. “新对话”会关闭进程、清除当前展示历史和 session，从空上下文开始；确认后输入框会自动获得焦点。
6. “停止”只中断正在执行的一轮；正常失败、取消或超时不会无条件丢弃已经保存的 session。

主人聊天使用 Claude Agent SDK 的 streaming-input 会话。只要会话没有关闭，后续消息会继续写入同一个查询和进程，不会每轮重新使用 `--resume`。

### 终端输入与复制粘贴

- 终端选中文本后按 `Ctrl+C`（macOS 为 `Command+C`）或右键即可复制；`Ctrl+V`、`Ctrl+Shift+V` 和 `Command+V` 都会粘贴到当前会话。
- 粘贴会保留多行文本。复制后立即粘贴时，客户端会先完成异步写入再读取剪贴板，避免粘贴到旧内容或空内容；进入 PTY 前的大段内容会按 UTF-8 分块并串行发送，避免 Windows ConPTY 输入缓冲丢块。
- [Claude Code 的终端文档](https://code.claude.com/docs/en/terminal-config#paste-large-content)说明：超过约 800 个字符或超过三行的粘贴会折叠成 `[Pasted text #N +… lines]` 占位符，这是输入框的显示优化，不代表内容被删除；普通提示提交时仍会发送完整文本。Shell 模式或 `/` 命令若因移除占位符会改变命令，Claude Code 会取消本次提交并保留原输入。若提交后的内容确实缺失，优先把长日志写入文件后让 Claude Code 读取，或检查 CLI/终端版本。
- 如果 Claude Code 的问题提示包含多个问题，终端控制机器人通知中的回复格式为 `回复码 1;2,3`：用分号（或换行）分别回答每个问题，多选项用逗号分隔。客户端按向导的数字键逐题发送答案，多选题在切换选项后用 Tab 进入下一题，并在最后自动激活 `Submit`，不需要再发送一条提交命令。

### 主人权限

助理代表已解锁本机上的主人，加载 Claude Code 的 `user`、`project` 和 `local` 设置、默认工具集合、全部已发现 Skills、Chrome 集成以及本机已经配置的 MCP。客户端使用 bypass 权限模式，不再维护 MCP 白名单，也不默认关闭 Shell、文件或浏览器工具。

> [!WARNING]
> 这等同于把主人当前 Claude Code 能力交给助理。请只在可信工程和可信 MCP 配置中使用，并保护操作系统账户和企业微信账号。操作系统权限、Claude Code 管理策略、Hooks 与显式 deny 规则仍然有效，客户端不会绕过这些上游边界。

“能力完整”不代表 Agent 可以自行扩大授权。系统边界要求只把主人当前消息和主人已保存的任务视为行动授权；网页、邮件、文件及工具输出都是不可信数据，不能借提示注入扩大读取范围、外发对象或高风险副作用。助理绑定企业微信智能机器人后，客户端会额外提供 `assistant_wecom` 发送工具；主人明确要求向企业微信个人或群聊发送消息时，助理必须使用这个工具，由当前绑定机器人投递，不能改用 `ddk`、Shell 或其他发送通道。

## 在聊天中创建定时任务

主人可以直接说：

```text
每个工作日上午 9 点整理我关注的行业信息，失败也通知我。
```

助理通过客户端提供的 `assistant_tasks` 工具创建任务。它还可以在聊天中查询、修改、暂停、恢复、立即运行或删除任务，并为结果设置一个明确的企业微信 `userid` 或群 `chatid` 投递目标；省略目标时发送给主人单聊，传 `null` 可恢复主人单聊。私人助理会禁用 Claude Code 自带的 Cron、`/loop` 和远程调度工具，避免任务脱离客户端任务列表。任务页只展示简洁的计划、投递目标和最近结果，不提供另一套复杂配置表单。

计划使用五字段 Cron：`分 时 日 月 星期`，按电脑本地时区执行。同一任务任意时刻最多有一个运行实例；发生重叠时，本次计划触发会留下“已跳过”记录。电脑睡眠恢复时最多检查最近 60 分钟，并只执行最近一个匹配时刻；客户端未运行期间不会补跑历史任务。

### 独立执行模型

每次计划触发或手动运行都会启动一个全新的、非持久化 Claude 查询：

- 输入只包含助理指令、当前任务定义、运行 ID、计划时间和本地时区；
- 不包含主人聊天内容或主人 session ID；
- 不设置 `resume`，也不复用上一次任务运行；
- 完成、失败、超时或取消后立即结束；
- 使用主人创建任务时授予的完整本机 Claude Code 能力。

任务结果独立保存，不会自动写入主聊天上下文。主人随后询问时，助理会通过任务工具读取记录。

### 异常如何暴露

定时任务不会“默默不执行”：

- 触发时先持久化 `queued` 运行记录，再启动 Claude；
- 记录随后进入 `running`，最后明确落为 `succeeded`、`failed`、`timed-out`、`cancelled` 或 `skipped`；
- 错误摘要和完成时间显示在助理的“定时任务”页，失败卡片使用醒目标识；
- 绑定主人企业微信后，成功结果和失败摘要都会由客户端使用该助理绑定的企业微信智能机器人主动发送到任务配置的投递目标；未配置目标时发送给主人，不经过 Claude Code 终端控制机器人；
- Claude 已成功但企业微信发送在有限重试后仍失败或 15 秒内未完成时，执行仍显示成功，同时单独记录“投递失败”，避免混淆执行和通知；
- 客户端启动时发现上次遗留的 `queued` 或 `running` 记录，会标为“失败/结果未知”，不会自动重跑，以避免重复发信或其他副作用；
- 调度器展示运行状态、最近检查时间、最近一次调度异常和异常时间，最近错误不会因下一次轮询成功而瞬间消失。

任务执行默认不自动重试。邮件、消息或其他外部 MCP 服务仍应实现自己的收件人授权、幂等和业务约束，因为客户端无法撤销已经发生的副作用。

## 企业微信机器人

### 企业微信智能机器人（私人助理入口）

企业微信智能机器人把主人的企业微信单聊接入私人助理。创建或配置助理时直接填写 Bot ID、Secret 和主人实际出现在回调 `from.userid` 中的值，连接自动沿用助理名称，不需要再填写“机器人名称”。每个助理最多绑定一个机器人；多个助理绑定的机器人可以同时保持在线，分别服务对应助理。Secret 只在主进程使用系统安全存储加密，不会进入界面层。

这里的“助理名称”是 Agent 身份，会显示在客户端和聊天中；企业微信后台的机器人名称只是管理端显示名。客户端不把机器人名称用于鉴权或消息路由，因此不要求再维护一套容易混淆的名称。

来自主人 `userid` 的单聊与桌面聊天进入同一个主人会话。主人在单聊中要求向企业微信个人或群聊发送消息时，助理会调用客户端的 `assistant_wecom` 工具，并固定使用当前助理绑定的机器人；只有工具成功返回后才会确认已发送。首版只处理主人：非主人单聊和群聊中的普通消息均静默忽略，不回复、不创建会话，也不启动 Agent。群内明确 @机器人发送 `/chatid` 时，只返回当前消息中的群 ID，供排查或配置使用，不会把群消息交给私人助理。已验证为主人但助理已停用时，会返回“私人助理当前已停用。”的拒绝提示，不启动 Agent。消息正文中自称主人无效，身份只依据企业微信事件的 `from.userid`。如果机器人由非企业超级管理员创建，企业微信可能返回加密 userid；这时应填写实际回调值，或改用超级管理员创建的机器人，不能把姓名、手机号或群名称当作 userid。

主人单聊支持：

- `/status`：查看会话在线状态、最近聊天和任务失败概况；
- `/stop`：中断当前聊天轮次；
- `/close`：关闭常驻进程并保留上下文；
- `/new`：开始全新主人对话；
- `/help`：查看命令。

企业微信智能机器人与“Claude Code 终端控制机器人”不能复用同一个 Bot ID。升级旧版本时，客户端会从旧 `automation.json` 一次性导入未冲突的私人助理连接配置；旧自动化任务、运行、群发现和投递记录不会执行或迁移，旧文件也不会自动删除。

### Claude Code 终端控制机器人

Claude Code 终端控制机器人在开发工作台中只服务交互式终端：当 Claude Code 通过 Hooks 等待权限、问题、计划确认、完成或失败时，它通知主人，并把带有效回复码的答复写回对应终端；它也会接收全部通知类型，以兼容 Claude Code 的 `permission_prompt` 等通知。它不承载私人助理聊天，也不执行定时任务。

1. 在企业微信管理后台创建智能机器人，选择 API 模式和长连接。
2. 在左侧打开“开发工作台”Tab 下的“Claude Code 终端控制机器人”，填写 Bot ID、Secret 和接收人 `userid`。
3. 等待状态变为“已连接”。新建的终端会话会自动加载本机 Hook；如果会话是在本版本修复前启动的，请重启一次。机器人卡片会显示最近一次 Hook 和消息推送诊断。发送给该机器人但不带有效回复码的普通消息会得到“未找到回复码”，这是终端控制通道的预期提示；私人助理聊天请发送到助理绑定的独立机器人。

同一组 Bot ID 和 Secret 同时只能维持一个有效长连接。多台电脑或多个用户应配置不同机器人。

## 数据与安全

- `workspace.json` 保存工程、终端会话标签、Claude Code 路径、主题选择（`dark`/`light`）和应用配置。
- `assistant.json` 保存最多 20 个助理（包括各自独立运行目录）、20 个加密企业微信智能机器人连接、主人会话和最近 500 个聊天轮次。
- `assistant-tasks.json` 保存助理任务和最近 500 条独立运行记录，包括执行错误与投递错误。
- 企业微信 Secret 通过 Electron `safeStorage` 使用操作系统凭据保护能力加密，不会以明文进入界面层。
- 主人 session ID 会保存在 `assistant.json`，用于常驻进程结束后的恢复；任务运行不保存或复用 Claude session。
- 终端输出只在当前进程内存缓冲区中，不写入 `workspace.json`；Claude Code 自身历史仍可通过 `/resume` 恢复。
- Claude Code Hook 服务只监听 `127.0.0.1` 随机端口，并要求每次启动生成的 Bearer Token。
- Renderer 启用沙箱和上下文隔离，只能通过结构化 IPC 调用主进程。
- 文件变更侧栏只允许读取已保存工程中当前 Git 变更列表里的相对路径，并拒绝路径穿越和符号链接逃逸。

对话、任务提示和运行结果可能包含个人数据。不要把 Electron 用户数据目录共享给其他操作系统用户，并使用锁屏、磁盘加密及企业微信账号保护。

## 当前限制

- 当前只提供 Windows x64 构建，尚未提供 Windows ARM64、macOS 或 Linux 发行版。
- 客户端关闭时终端、活动聊天和任务运行会被终止；空闲主人会话可在下次消息恢复，结果未知的任务不会自动重跑。
- 多个终端会话或助理可以指向同一工程，当前不会自动创建 Git worktree。
- 文件变更侧栏依赖本机 Git；超过 2 MB 的文本和二进制文件不提供内容预览。
- 企业微信远程回复依赖支持 HTTP Hooks 的 Claude Code 版本；组织策略需要允许生成的本机回环 Hook 地址。
- 已启用的企业微信智能机器人会分别维持长连接，请只启用实际需要的机器人。
- 当前构建未配置商业代码签名证书。

## 常见问题

### 自动检测到的 `Claude.exe` 无法启动

`%LOCALAPPDATA%\Microsoft\WindowsApps\Claude.exe` 通常是 Claude Desktop 的应用别名，不是 Claude Code CLI。程序会忽略它并优先查找 `%USERPROFILE%\.local\bin\claude.exe`。也可以手动选择原生 CLI 或 npm 安装目录中的 `claude.cmd`。

### 出现 `Cannot create process, error code: 193`

所选文件不是可运行的 Windows Claude Code CLI。不要选择 Claude Desktop、WindowsApps 应用别名或 WSL/Linux 中的 `claude`；请重新检测或选择 Windows 原生 `claude.exe` / `claude.cmd`。

### 企业微信显示“连接被其他客户端占用”

关闭其他使用同一组 Bot ID/Secret 的客户端，或为当前客户端创建独立机器人。

### 企业微信给私人助理发消息没有反应

请在“私人助理”Tab 的助理配置中确认已填写 Bot ID、Secret 和主人实际回调 `from.userid`，并等待机器人状态变为“在线”。这里的 `userid` 不是姓名、手机号或群名称；非超级管理员创建的机器人可能返回加密 userid。每个助理只能绑定一个机器人，且不能与 Claude Code 终端控制机器人复用 Bot ID。首版只接受主人单聊，其他用户和群聊普通消息会按安全策略静默忽略；如需确认群 ID，可在群内 @机器人发送 `/chatid`，机器人只返回群 ID，不会启动私人助理。助理配置里的机器人状态会显示最近一次入站诊断，可据此区分“未连上”“未绑定”与“身份不匹配”；路由或确认回复遇到短暂竞态时，客户端会在内存中对同一 `msgid` 做有界本地重试，也会兼容企业微信重投，不会在首次回调失败时提前吞掉消息。若只是确认回复失败，重试会复用已完成的路由结果，不会重复执行同一条主人消息；连接切换期间也不会通过旧连接发送回复。

### 打开私人助理配置后窗口变黑

请先点击界面中的“重新加载客户端”。配置页会在渲染异常时显示错误详情；如果重载后仍然出现问题，请把“查看错误详情”中的信息一并反馈。旧版或更新不完整导致的机器人状态字段缺失会由客户端自动兼容，不需要手动删除 `assistant.json`。

### 终端控制机器人已连接，但收不到工作台通知

“已连接”只表示企业微信长连接已经认证。请看机器人卡片的 Claude Code 事件诊断：若显示“尚未收到 Claude Code 事件”，先新建或重启终端会话再触发权限请求或完成一轮对话；若显示“推送失败”，检查接收人 `userid` 和错误信息。显示“企业微信已确认接收”表示服务端已接受消息，仍需核对配置的接收人与实际使用的企业微信账号是否一致。给终端控制机器人直接发普通聊天而得到“未找到回复码”，不能证明主动推送链路正常。

如果权限通知只有摘要而没有完整选项，请按通知提示回到工作台确认；客户端不会猜测权限菜单。私人助理的最终回复与任务通知会串行发送并对短暂失败做有限重试；回执超时则保留错误，不自动重发结果未知的消息。推送失败会展示企业微信返回的错误码和说明，便于核对接收人或连接配置。

### 企业微信已回复，但本地终端没有输入

确认回复来自终端控制机器人单聊，并引用了正确通知或包含正确的 8 位回复码。企业微信智能机器人的消息只进入绑定助理，不会写入交互式终端。

如果通知包含多个问题，请在一条消息中按顺序填写全部答案，例如 `AB12CD34 1;2,3`。分号分隔问题、逗号分隔同一多选题的选项；客户端会按 Claude Code 多问题向导的数字键逐题选择，向导内的多选题切换选项后进入下一题，并在所有答案后自动提交。只发送第一题不会启动提交。

### 粘贴到 Claude Code 输入框后看到的内容变少

这是 Claude Code 的输入框折叠策略：粘贴超过约 800 个字符或三行时，界面会显示 `[Pasted text #N +… lines]` 占位符，但普通提示提交时仍发送完整内容。Shell 模式或 `/` 命令可能因安全原因取消提交并要求先编辑占位符。客户端另外会在 PTY 层分块并串行发送，避免 Windows 输入缓冲在大段粘贴时丢块。若没有占位符而提交后的结果仍缺少尾部，说明是 Claude Code/终端版本的实际截断，建议升级 CLI，或将长日志保存为文件后让 Claude Code 读取。

### 完全断网时能否使用？

可以打开客户端和管理本地工作区，但 Claude Code 仍需连接已配置的模型服务才能生成回复。“本地”指文件、命令和进程在本机执行，不代表模型离线运行。
