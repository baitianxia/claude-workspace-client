# Claude Workspace

> 面向 Windows 的本地私人助理与多工程 Claude Code 桌面工作台

[快速开始](#快速开始) · [私人助理 Agent](#私人助理-agent) · [定时任务](#在聊天中创建定时任务) · [企业微信](#企业微信入口) · [数据与安全](#数据与安全) · [常见问题](#常见问题)

Claude Workspace 在一个桌面窗口中组织本机 Claude Code 工程会话，并提供多个独立的私人助理 Agent。助理可以在客户端内直接聊天，也可以从主人的企业微信单聊继续同一段上下文；网页读取、邮件处理、信息推送和定时执行都属于助理能力，不再有独立的“网页信息推送自动化”产品。

> [!IMPORTANT]
> Claude Workspace 不包含、代理或重新实现 Claude Code。它使用电脑上已经安装并登录的 Claude Code CLI。文件、命令和工具在本机执行，模型请求仍由 Claude Code 发往你配置的 Anthropic、Amazon Bedrock、Google Vertex AI、Microsoft Foundry 或企业网关；这不是离线模型客户端。

## 功能亮点

| 能力 | 说明 |
| --- | --- |
| 私人助理 Agent | 创建多个独立助理，在客户端聊天；主人企业微信单聊与本地共享同一段连续上下文 |
| 完整主人能力 | 助理加载主人本机的 Claude Code 用户、工程和本地设置，可使用默认工具、Skills、Chrome 和已配置 MCP |
| 会话内定时任务 | 直接在聊天中让助理创建、修改、暂停、运行或删除任务，无需复杂配置页 |
| 独立任务执行 | 每次任务运行使用全新的一次性 Claude 会话，不读取或污染主人聊天历史 |
| 异常可见 | 执行失败、超时、中断、重叠跳过、启动恢复和企业微信投递失败都有持久记录 |
| 多企业微信入口 | 多个启用的助理入口可同时在线，每个助理选择一个入口；与 Claude Code 管理机器人明确分开 |
| 多工程工作区 | 添加多个本地项目，以真实工程目录作为 Claude Code 的 `cwd` |
| 原生终端体验 | 保留 Claude Code TUI、权限确认、斜杠命令、ANSI 输出和键盘交互 |
| 文件变更查看 | 查看 Git 变更、相对 `HEAD` 的对比和磁盘最新内容，支持 Markdown、GFM 与 Mermaid |
| 企业微信远程回复 | Claude Code 终端等待权限、问题或计划确认时，可通知主人并接收远程输入 |

## 快速开始

### 运行要求

- Windows 10 或 Windows 11，x64 架构。
- 已按照 [Claude Code 官方文档](https://code.claude.com/docs/en/setup) 安装并登录 Claude Code。
- 能够访问 Claude Code 所使用的模型服务或企业网关。
- Git（仅“文件变更”侧栏需要）。
- Node.js 只在从源码开发或构建时需要。

先在普通 PowerShell 中确认 Claude Code 可以独立运行：

```powershell
where.exe claude
claude --version
claude
```

### 安装和首次使用

1. 解压 `Claude Workspace-<版本号>-x64.zip`，不要直接在压缩包内运行。
2. 双击 `Claude Workspace.exe`。
3. 点击“选择工程文件夹”，添加实际项目根目录。
4. 在工程下新建 Claude Code 会话，或创建相互隔离的临时会话。
5. 使用左侧列表或 `Ctrl+K` 切换工程与会话。
6. 需要私人助理时，打开“私人助理 Agent”，新建助理并选择它的运行工程。

程序会自动查找原生安装的 `claude.exe` 和 npm 安装产生的 `claude.cmd`。自动检测失败时，可以手动选择 `.exe`、`.cmd`、`.bat` 或 `.ps1` 启动文件。

## 私人助理 Agent

私人助理独立于接入渠道，不是企业微信机器人的别名。每个助理保存自己的名称、指令、运行工程、主人身份、连续 Claude 会话和定时任务；没有企业微信也可在桌面完整使用。

### 创建并聊天

1. 在左侧打开“私人助理 Agent”，点击“新建助理”。
2. 填写名称并选择运行工程；助理指令可选。
3. 保存后直接发送消息。`Enter` 发送，`Shift+Enter` 换行；同一助理按顺序处理消息，不同助理可并行。
4. “关闭会话”只结束当前常驻 Claude 进程并保留上下文；下一条消息会恢复已保存的 session。
5. “新对话”会关闭进程、清除当前展示历史和 session，从空上下文开始。
6. “停止”只中断正在执行的一轮；正常失败、取消或超时不会无条件丢弃已经保存的 session。

主人聊天使用 Claude Agent SDK 的 streaming-input 会话。只要会话没有关闭，后续消息会继续写入同一个查询和进程，不会每轮重新使用 `--resume`。

### 主人权限

助理代表已解锁本机上的主人，加载 Claude Code 的 `user`、`project` 和 `local` 设置、默认工具集合、全部已发现 Skills、Chrome 集成以及本机已经配置的 MCP。客户端使用 bypass 权限模式，不再维护 MCP 白名单，也不默认关闭 Shell、文件或浏览器工具。

> [!WARNING]
> 这等同于把主人当前 Claude Code 能力交给助理。请只在可信工程和可信 MCP 配置中使用，并保护操作系统账户和企业微信账号。操作系统权限、Claude Code 管理策略、Hooks 与显式 deny 规则仍然有效，客户端不会绕过这些上游边界。

“能力完整”不代表 Agent 可以自行扩大授权。系统边界要求只把主人当前消息和主人已保存的任务视为行动授权；网页、邮件、文件及工具输出都是不可信数据，不能借提示注入扩大读取范围、外发对象或高风险副作用。

## 在聊天中创建定时任务

主人可以直接说：

```text
每个工作日上午 9 点整理我关注的行业信息，失败也通知我。
```

助理通过客户端提供的 `assistant_tasks` 工具创建任务。它还可以在聊天中查询、修改、暂停、恢复、立即运行或删除任务。任务页只展示简洁的计划和最近结果，不提供另一套复杂配置表单。

计划使用五字段 Cron：`分 时 日 月 星期`，按电脑本地时区执行。同一任务任意时刻最多有一个运行实例；发生重叠时，本次计划触发会留下“已跳过”记录。电脑睡眠恢复时最多检查最近 60 分钟，并只执行最近一个匹配时刻；客户端未运行期间不会补跑历史任务。

### 独立执行模型

每次计划触发或手动运行都会启动一个全新的、非持久化 Claude 查询：

- 输入只包含助理指令、当前任务定义、运行 ID、计划时间和本地时区；
- 不包含主人聊天内容或主人 session ID；
- 不设置 `resume`，也不复用上一次任务运行；
- 完成、失败、超时或取消后立即结束；
- 使用主人创建任务时授予的完整本机 Claude Code 能力。

任务结果独立保存，不会自动写入主聊天上下文。主人随后询问时，助理会通过任务工具读取记录。

### 异常如何暴露

定时任务不会“默默不执行”：

- 触发时先持久化 `queued` 运行记录，再启动 Claude；
- 记录随后进入 `running`，最后明确落为 `succeeded`、`failed`、`timed-out`、`cancelled` 或 `skipped`；
- 错误摘要和完成时间显示在助理的“定时任务”页，失败卡片使用醒目标识；
- 绑定主人企业微信后，成功结果和失败摘要都会主动发送给主人；
- Claude 已成功但企业微信发送失败或 15 秒内未完成时，执行仍显示成功，同时单独记录“投递失败”，避免混淆执行和通知；
- 客户端启动时发现上次遗留的 `queued` 或 `running` 记录，会标为“失败/结果未知”，不会自动重跑，以避免重复发信或其他副作用；
- 调度器展示运行状态、最近检查时间、最近一次调度异常和异常时间，最近错误不会因下一次轮询成功而瞬间消失。

任务执行默认不自动重试。邮件、消息或其他外部 MCP 服务仍应实现自己的收件人授权、幂等和业务约束，因为客户端无法撤销已经发生的副作用。

## 企业微信入口

### 私人助理入口

在助理配置中可选择一个“企业微信助理入口”，并填写主人真实的企业微信 `userid`。入口管理只需要本机名称、Bot ID、Secret 和启用状态；多个启用入口可以同时保持在线，未来可分别服务不同助理。

来自主人 `userid` 的单聊与桌面聊天进入同一个主人会话。首版只处理主人：非主人单聊和所有群聊均静默忽略，不回复、不创建会话，也不启动 Agent。消息正文中自称主人无效，身份只依据企业微信事件的 `from.userid`。

主人单聊支持：

- `/status`：查看会话在线状态、最近聊天和任务失败概况；
- `/stop`：中断当前聊天轮次；
- `/close`：关闭常驻进程并保留上下文；
- `/new`：开始全新主人对话；
- `/help`：查看命令。

助理入口与“Claude Code 管理机器人”不能复用同一个 Bot ID。升级旧版本时，客户端会从旧 `automation.json` 一次性导入未冲突的企业微信入口；旧自动化任务、运行、群发现和投递记录不会执行或迁移，旧文件也不会自动删除。

### Claude Code 管理机器人

Claude Code 管理机器人只服务交互式终端：当 Claude Code 通过 Hooks 等待权限、问题、计划确认或完成回复时，它通知主人，并把带有效回复码的答复写回对应终端。它不承载私人助理聊天，也不执行定时任务。

1. 在企业微信管理后台创建智能机器人，选择 API 模式和长连接。
2. 在左侧打开“Claude Code 管理机器人”，填写 Bot ID、Secret 和接收人 `userid`。
3. 等待状态变为“已连接”，再新建或重启需要远程回复的终端会话。

同一组 Bot ID 和 Secret 同时只能维持一个有效长连接。多台电脑或多个用户应配置不同机器人。

## 数据与安全

- `workspace.json` 保存工程、终端会话标签、Claude Code 路径和应用配置。
- `assistant.json` 保存最多 20 个助理、20 个加密助理入口、主人会话和最近 500 个聊天轮次。
- `assistant-tasks.json` 保存助理任务和最近 500 条独立运行记录，包括执行错误与投递错误。
- 企业微信 Secret 通过 Electron `safeStorage` 使用操作系统凭据保护能力加密，不会以明文进入界面层。
- 主人 session ID 会保存在 `assistant.json`，用于常驻进程结束后的恢复；任务运行不保存或复用 Claude session。
- 终端输出只在当前进程内存缓冲区中，不写入 `workspace.json`；Claude Code 自身历史仍可通过 `/resume` 恢复。
- Claude Code Hook 服务只监听 `127.0.0.1` 随机端口，并要求每次启动生成的 Bearer Token。
- Renderer 启用沙箱和上下文隔离，只能通过结构化 IPC 调用主进程。
- 文件变更侧栏只允许读取已保存工程中当前 Git 变更列表里的相对路径，并拒绝路径穿越和符号链接逃逸。

对话、任务提示和运行结果可能包含个人数据。不要把 Electron 用户数据目录共享给其他操作系统用户，并使用锁屏、磁盘加密及企业微信账号保护。

## 当前限制

- 当前只提供 Windows x64 构建，尚未提供 Windows ARM64、macOS 或 Linux 发行版。
- 客户端关闭时终端、活动聊天和任务运行会被终止；空闲主人会话可在下次消息恢复，结果未知的任务不会自动重跑。
- 多个终端会话或助理可以指向同一工程，当前不会自动创建 Git worktree。
- 文件变更侧栏依赖本机 Git；超过 2 MB 的文本和二进制文件不提供内容预览。
- 企业微信远程回复依赖支持 HTTP Hooks 的 Claude Code 版本；组织策略需要允许生成的本机回环 Hook 地址。
- 已启用的助理入口会分别维持长连接，请只启用实际需要的入口。
- 当前构建未配置商业代码签名证书。

## 常见问题

### 自动检测到的 `Claude.exe` 无法启动

`%LOCALAPPDATA%\Microsoft\WindowsApps\Claude.exe` 通常是 Claude Desktop 的应用别名，不是 Claude Code CLI。程序会忽略它并优先查找 `%USERPROFILE%\.local\bin\claude.exe`。也可以手动选择原生 CLI 或 npm 安装目录中的 `claude.cmd`。

### 出现 `Cannot create process, error code: 193`

所选文件不是可运行的 Windows Claude Code CLI。不要选择 Claude Desktop、WindowsApps 应用别名或 WSL/Linux 中的 `claude`；请重新检测或选择 Windows 原生 `claude.exe` / `claude.cmd`。

### 企业微信显示“连接被其他客户端占用”

关闭其他使用同一组 Bot ID/Secret 的客户端，或为当前客户端创建独立机器人。

### 企业微信已回复，但本地终端没有输入

确认回复来自 Claude Code 管理机器人单聊，并引用了正确通知或包含正确的 8 位回复码。私人助理入口的消息只进入绑定助理，不会写入交互式终端。

### 完全断网时能否使用？

可以打开客户端和管理本地工作区，但 Claude Code 仍需连接已配置的模型服务才能生成回复。“本地”指文件、命令和进程在本机执行，不代表模型离线运行。
